AI readers often stop reading a file after about 100 lines and work from what they saw. A table of contents inside the first 100 lines tells the reader what the rest of the file holds, so it can jump to the section it needs instead of guessing. Applies to every document written for a project (docs vault, repo docs, ADRs, audits, handoffs, specs, runbooks), by a person or by AI.

## The rule

1. **Any document over 60 lines has a `## Contents` list, and the list starts within the first 40 lines** (always inside the first 100). Shorter documents do not need one.
2. **It is generated by `/home/jac/.claude/scripts/doc-toc.mjs`**, so it never goes stale by hand-editing. A document without it, or with a stale one, is not done (`definition-of-done.md`).
3. **Anything that must be read first goes above the list or in the first section** (status, purpose, "read this before X"). Keep the part above the list short.

## Where it goes

Directly under the H1 title and its one-line intro (an italic or `>` line), before any other section. The generator puts it there between `<!-- toc -->` and `<!-- /toc -->` markers; it only rewrites what is between the markers. Frontmatter (the `---` block) stays first; a long frontmatter counts toward the 100 lines, so keep it under 25.

## What it lists

H2 and H3 headings, one per line, as links. Vault documents use `[[#Heading]]` links (Obsidian); documents in a repo use `[Heading](#slug)` (`--style=md`). A file with more than 40 headings lists H2 only. Make headings say what the section holds ("Rollback steps", not "Notes") because the list is how the reader chooses.

## Generate it, do not hand-write it

```
node /home/jac/.claude/scripts/doc-toc.mjs <folder-or-file>...            # write or refresh
node /home/jac/.claude/scripts/doc-toc.mjs --check <folder-or-file>...    # exit 1 if one is missing or stale
node /home/jac/.claude/scripts/doc-toc.mjs --style=md README.md           # repo docs
```

A hand-written `## Contents` list without markers is adopted (replaced in place by the generated one), never duplicated. Run it as the last step after editing docs, and before saying a docs change is done. It skips `archive/`, `images/` and `node_modules/` (frozen copies are not touched), and ignores headings inside code fences.

## Very long files

A file over 400 lines, or a changelog or log where one section is one dated entry, also gets, above the list, a line of reading guidance: where the newest content is, what to grep for, which section answers which question ("newest first; search `## Unreleased` for open work"). If it is over about 1000 lines, split it (`pure-move-refactors.md`) or archive the old part.

## Exceptions

- Frozen archives (`archive/`): not touched.
- Files a tool parses (JSON Canvas, `.base`, templates with required first lines): none needed.
- A document under 60 lines: optional.

## Onboarding and new documents

- When a project is onboarded, run the script over its docs folder and the repo's `README.md`/`SETUP.md`/ADR folder, and add `--check` to its checks if it has a docs check.
- When Claude writes a new document, it runs the script on that file before finishing.
- `_PriorityRead.md` lists the long documents worth reading first; the TOC says what is in each one.

Enforcer: a PostToolUse hook (`~/.claude/hooks/doc-toc.sh`, registered in `settings.json`) refreshes the list of any `.md` under `DevHiveMind/Projects/` right after Write/Edit; `doc-toc.mjs --check` (exit 1 when missing or stale). Run it in a project's `check` or pre-push hook when that project wants it enforced; until then it is advisory and part of the docs line of the Definition of done.
