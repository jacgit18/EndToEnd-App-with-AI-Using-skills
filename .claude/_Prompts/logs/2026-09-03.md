## Response to the user

Both of your instincts point the same way once the nightly batch is in the picture.

**1. `order_lines` as its own table — yes, not a JSON column.**

The "fetch an order with all its lines" pattern doesn't actually favor JSON. It's a single indexed read: `SELECT ... FROM order_lines WHERE order_id = ?`, ~5 rows via one index lookup. JSON doesn't beat that meaningfully.

What JSON *costs* you here:
- The nightly "sum revenue by product" batch has to scan every `orders` row and unnest JSON with no index on product — a full table scan of 2M+ rows/year that grows forever. With a real table it's an indexed aggregate on `product_id`.
- No FK to `products`, no per-line `CHECK` (quantity &gt; 0, non-negative price), no referential integrity — and your line has real queryable attributes (`product_id`, `quantity`, `unit_price`) participating in their own query.

JSON denormalization earns its place only when the child is opaque — never queried independently, never aggregated, no FK needs. You have all three against you. This is a textbook 3NF parent/child; keep it normalized.

**2. Indexes on `order_lines`:**

| Index | Serves |
|---|---|
| `order_lines(order_id)` | the per-request "order with all its lines" — the critical one. If your PK is a composite `(order_id, line_no)` the leading column already covers this; if it's a surrogate `bigint`, add this explicitly. |
| `order_lines(product_id)` — consider `INCLUDE (quantity, unit_price)` | the nightly revenue-by-product rollup; the covering columns let it aggregate from the index without heap fetches. |

Notes:
- Postgres does **not** auto-index FK columns — both `order_id` and `product_id` FK indexes must be created by hand.
- If the revenue batch is date-bounded ("yesterday", "last month"), it needs a date dimension too — either put `created_at` on `order_lines` or have the batch join `orders` on `order_date` with `orders(order_date)` indexed. Decide which before you settle the `product_id` index shape.
- Nothing else is justified by the patterns you gave — don't index `quantity`, `unit_price`, or `line_no` alone.
