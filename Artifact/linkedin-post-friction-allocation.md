Early in a career, most of the curriculum is friction you didn't choose. The blind debugging session. Reading a library's source because the docs stopped short. Writing boilerplate by hand until the pattern sticks instead of getting looked up again.

AI can clear almost all of that now. Ask, and the boilerplate appears, the stack trace gets explained, the docs get summarized. Real gain — and also how the reps quietly go missing. Not because anyone decided you didn't need them. Because the easy path stopped requiring them.

What I didn't expect: I can take that friction back on purpose. And I can use the same tool to decide where.

Not one blanket answer to "should I use AI here." A per-decision one.

A gate that makes me state a hypothesis before it'll help me debug.

A rule that a build gets delivered one file at a time when I'm the one who has to own the result — and all at once when I don't.

I recently reviewed my own paced-build process against how it actually held up on a real build. Two of the three gaps it found were real, not false alarms. The process caught itself being wrong and got more precise, not softer.

Offloading isn't the skill. Knowing which friction is yours to keep is.
